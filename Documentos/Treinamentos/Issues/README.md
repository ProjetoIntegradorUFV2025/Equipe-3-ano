# 📝 Issues

Este repositório utiliza **Issues do GitHub** como forma principal de acompanhamento de tarefas, bugs e melhorias. Para garantir uma boa organização, seguimos um padrão baseado em **Templates**, **Labels** e **Milestones**.

---

## 📌 Templates de Issues
Ao abrir uma nova Issue, você deve escolher o **tipo de template** adequado, localizado na pasta [`/.github/ISSUE_TEMPLATE`](../../.github/ISSUE_TEMPLATE/):

- **Bug** 🐞 – para relatar erros ou falhas encontradas.  
- **Feature** ✨ – para sugerir ou documentar novas funcionalidades.  
- **Fix** 🔧 – para ajustes ou melhorias pequenas no código/projeto.  

> Caso seja necessário um novo padrão de template, abra uma **Issue do tipo Feature** requisitando a criação desse modelo, explicando sua proposta.

---

## 🏷️ Labels
As **Labels** ajudam a identificar rapidamente a categoria e o status de cada Issue.  

- Devem ser usados, prioritariamente, os **labels padrão do GitHub** (como `bug`, `enhancement`, `documentation`).  
- Foi criado também um label especial:  
  - **`accepted`** ✅ – usado para marcar Issues que já foram analisadas e aprovadas para execução.  

Se houver necessidade, novos labels podem ser criados clicando em **“New Label”**.

---

## 📆 Milestones
Para organizar as tarefas dentro das **sprints**, utilizamos **Milestones**:

- Cada **sprint** corresponde a um **Milestone**.  
- Ao criar uma nova Issue, **atribua o Milestone da sprint atual**.  
- Isso garante que todas as demandas fiquem centralizadas e possam ser priorizadas de acordo com o planejamento.  

Se precisar criar um novo Milestone, basta clicar em **“New Milestone”** no GitHub.

## ✅ Fluxo Resumido

1. Criar uma Issue selecionando o **template** adequado.  
2. Atribuir o **Milestone da sprint atual**.  
3. Usar **Labels** para classificação (incluindo `accepted`, se aprovado).  
4. Acompanhar o progresso da Issue dentro da sprint via **Milestones**.
